# To-do list d'une affaire — plan de réalisation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remplacer la page d'attente « To-do list » par un module complet : liste de mission par phase, tâches du quotidien, contenu des plans, liste type modifiable enregistrée dans Supabase, partage par lien.

**Architecture:** Deux tables (migration 066) : `todo_modele` (liste type de l'agence, remplie par la migration) et `todo_elements` (tout ce qui appartient à une affaire). Toute la logique d'affichage est pure dans `todoLogique.js` (testée) ; les lectures et écritures dans `todoDonnees.js` ; l'écran dans `src/modules/etude/todo/`.

**Tech Stack:** React 19, Supabase (postgrest-js), node --test.

**Spec:** `docs/superpowers/specs/2026-10-09-todo-list-design.md`

## Global Constraints

- Français partout (code métier, commentaires, commits `feat:` / `fix:` / `test:` / `docs:`).
- Styles inline, couleurs du cadre par `var(--affaire-accent…)`.
- Fenêtre jamais fermée au clic à côté ; tout bouton `type="button"`.
- Supabase ne lève pas d'exception : toujours lire `{ error }`.
- Code tolérant à l'absence de la migration 066 (`PGRST205` / `42P01` → « pas encore installée »).
- Aucune liste d'articles dans le code : la liste type n'existe que dans la migration (SQL) et en base.
- `npm run build` et `npm test` doivent passer avant chaque commit ; commit et push en fin de travail.

### Task 1 : logique pure (`todoLogique.js`) et ses tests

**Produces :**
- `PHASES_MISSION` : `[{ code, libelle, court }]` — `engagement`, `esq`, `aps`, `apd`, `pro`, `dce`, `act`, `prepa`, `det`, `aor`.
- `RUBRIQUES_PLANS` : `[{ code, libelle }]` — `masse`, `sous_sol`, `rdc`, `etages`, `terrasse`, `charpente`, `coupes`, `facades`, `details`, `reglementaire`.
- `groupesDe(liste)` → l'une des deux listes.
- `articlesAffiches(modele, elements, liste)` → `Article[]`, où `Article = { cle, source: 'modele'|'article', modeleId, elementId, liste, groupe, texte, ordre, fait_le, fait_par, sans_objet, note, retire }` ; un article type supprimé n'apparaît que s'il a été touché (coche, note, sans objet), avec `retire: true`.
- `estGrise(article)` → `sans_objet || retire`.
- `compteur(articles)` → `{ faits, total }`, hors grisés.
- `parGroupe(articles, liste)` → `[{ code, libelle, court?, articles (actifs puis grisés, par ordre), compteur }]`.
- `phaseParDefaut(phaseAffaire, groupes)` → code (correspondance de la spec, section 5).
- `enRetard(tache, aujourdhui)`, `tachesTriees(taches, aujourdhui)` → `{ aFaire, faites }`.
- `lienPartage(origine, affaireId, { onglet, phase, tache })`, `lireLien(search)` → `{ onglet, phase, tache }`.
- `nomPersonne(id, profils)`, `libelleFait(element, profils)` → « Fait par Victor le 09/10 ».
- `ordreSuivant(articles, groupe)`.
- `resumeTuile(modele, elements, phaseAffaire, aujourdhui)` → `{ phase, court, faits, total, tachesAFaire, tachesEnRetard }`.
